# 时间线界面方案

> 目标：一屏看到「她这一天」，横轴是时间，纵向标注状态变化。
> 位置：后台首页（替换现在的「关于你」作为默认页）。

---

## 一、数据结构：现在有什么、缺什么

| 要用到的 | 现在有没有 | 说明 |
|---|---|---|
对话事件（谁说了什么） | ✅ | `turns` 有 at + perception + act + scene 快照 |
主动消息 | ✅ | `messages` 里 meta.proactive=true |
她的事件情绪 | ✅ | `state.affectEvents` 带 at + 半衰期，可反推任意时刻 |
每轮花费 | ✅ | `usage` 有 created_at + cost |
**场景变化历史** | ❌ | 只存了当前场景 + 最近 4 条（无时间戳） |
**他的情绪历史** | ❌ | `uaffect` 只存当前值，没有快照 |

所以要补两个记录：

```sql
-- 场景切换时写一条
CREATE TABLE scene_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  qq TEXT NOT NULL,
  at INTEGER NOT NULL,
  scene_id TEXT,
  location TEXT,
  doing TEXT,
  pace TEXT,
  chat REAL
);

-- 每轮把"她以为的他"快照一份（或直接并进 turns）
ALTER TABLE turns ADD COLUMN he TEXT;
```

两个都是**只增不改**，不影响现有逻辑，各 10 行代码。

## 三、六条轨道（自上而下）

### ① 时段带

由 preset 参数算：早间 7.2-8.2 / 上午 9-12 / 午间 12-13 / 下午 13-18 / 晚间 18-21.5 / 夜间 21.5-24。
浅色块 + 极淡文字，只做背景。

### ② 场景条带

每段一个色块，色相按 `place`：

```
home 米黄 · commute 蓝灰 · work 靛 · outside 绿 · shop 橙 · bed 紫
```

块内写 `location · doing`，放不下只写 location。
hover：手头事项（pending/doing/done）+ pace + chat。

### ③ 她的情绪

两条叠在一起：

```
主曲线：愉悦度 v（-1~1），填充面积，正区绿、负区红
虚线：激活度 a（0~1），右轴
```

数据来源：`affectEvents` 在任意时刻 t 累加衰减值，逐点算（每 10 分钟一个点，一天 144 个点，纯本地）。

### ④ 他的情绪

`turns.he` 快照折线（每轮一个点），断点表示没聊。
低于 -0.35 的区域标浅红底，对应"她判断他不好"。

### ⑤ 事件层

```
对话      实心圆（他发的）/ 空心圆（她回的），悬停看原文
主动消息  三角，向上
情绪事件  五角星，红色负面、绿色正面（场景事项完成引发的那些）
```

### ⑥ 花费

每小时一根柱，高度=该小时累计花费，标注总额。

## 四、交互

```
hover     任一轨道 → 竖线 + 卡片：那一刻的场景/情绪/最近一句
click     事件点 → 跳到「对话回放」对应轮次
拖动      框选时间段 → 只看这段
切换      今天 / 昨天 / 选日期；24 小时 / 最近 6 小时 / 最近 1 小时
```

## 六、技术选型

```
React + 原生 SVG（不加图表库）
  · 一条 <svg viewBox="0 0 1440 420">，六条轨道各一个 <g>
  · 曲线用 <polyline>，条带用 <rect>，事件用 <circle>/<path>
  · hover 用 mousemove + state 定位，不引第三方
理由：依赖零增加、打包体积不变、颜色和现有设计系统一致
```

## 七、接口

```
GET /api/timeline?qq=&date=2026-10-30&span=24h
→ {
    bands:  [{ name, label, from, to }],
    scenes: [{ at, until, location, doing, pace, chat, items }],
    affect: [{ t, v, a }],           // 每 10 分钟
    he:     [{ t, v, a, confidence }],
    events: [{ t, type: 'user'|'her'|'proactive'|'mood', text, turnId }],
    cost:   [{ hour, yuan }],
  }
```

一次请求，前端只画不算。

## 八、分三步做

| 阶段 | 内容 | 工时 | 能看到的 |
|---|---|---|---|
1 | 情绪曲线 + 事件点 + 花费柱 | 0.5 天 | 今天的情绪起伏、聊了几次 |
2 | 补 `scene_log` → 场景条带 | 0.5 天 | 她一天换了几次场景 |
3 | 补 `turns.he` → 他的曲线；hover/点击/框选 | 0.5 天 | 两条情绪对照 |

**阶段 1 不需要改任何后端表**，只加一个接口，数据全在。

---

## 九、风险

| 风险 | 应对 |
|---|---|
数据太稀（一天只聊两句） | 空轨道显示淡线，不强行画 |
情绪曲线失真 | 事件带半衰期，逐点算而不是插值 |
一次请求太重 | 服务端聚合到 10 分钟粒度，24h ≈ 144 点 |
时区 | 全部用本地时区，日期按本地切 |
