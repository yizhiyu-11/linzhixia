> 2026-10-30。基于对线上 246 条感知记录、597 条消息的审计，以及场景/情绪/裁决三层的方案文档。

---

## 一、现在在做什么（一句话版）

给"林知夏"补上三样东西，让她像真人而不是客服：

```
① 场景层：她的一天有具体的事（在做什么、刚做完什么）
② 情绪层：情绪由事件产生、会延续、会影响之后的话和事
③ 裁决层：这一轮该接住、还是说点自己的
```

感知层已有，但它的"情绪"需要重新定义（见第三节）。

## 三、感知层情绪审计（重点）

### 3.1 线上数据

```
user 消息 291 条 → 感知记录 246 条，覆盖率 84.5%（15.5% 失败退回规则）
情绪分布：平静 65% · 撒娇 22% · 开心 13% · 焦虑 1% · 生气 0% · 难过 0%
意图分布：试探 32% · 分享 28% · 提问 20% · 敷衍 15% · 倾诉 3%
certainty：平均 0.70，最低 0，最高 0.95
情绪翻转：87 次 / 246 条 = 35.4%
```

### 3.2 结论：现在的"情绪"是语气分类，不是状态

四条硬伤：

| # | 问题 | 证据 |
|---|---|---|
1 | **只有类别，没有强度** | "有点烦"和"气炸"都记成"生气" |
2 | **没有延续性** | 每轮独立判断，翻转率 35.4%（三轮翻一次） |
3 | **负向情绪几乎不出现** | 难过 0%、生气 0%、焦虑 1%——模型不敢判负面 |
4 | **没有来源** | 不知道"因为谁、因为什么" |

另外两个工程问题：

```
· 15.5% 感知失败（视觉模型返回坏 JSON 时直接退回规则，无降级策略）
· 每条消息一次模型调用（"嗯""哦"这类短消息其实规则就够）
```

### 3.3 改造建议：职责分离

**感知层只做两件事**：

```
① 句子级语气（toneHint）：这句话什么味 → 强度 0-1
② 事件抽取（appraisal）：他对她做了什么 → 供情绪层使用
```

**情绪状态归情绪层**（affect.mjs），感知层不再假装"情绪"。

具体改动：

```js
// 现在
{ emotion: '撒娇', intent: '试探', certainty: 0.7 }

// 改成
{
  tone: { label: '撒娇', intensity: 0.6 },      // 句子级
  event: { kind: 'praise', toward: 'her', impact: +0.4 },  // 他对她做了什么
  intent: '试探', certainty: 0.7
}
```

`event` 的候选（有限枚举）：

```
praise 夸她 / ignore 冷落 / blame 凶她 / comfort 安慰
ask 关心她 / tease 逗她 / reject 拒绝 / share 分享自己的事
```

**这样"她生气"就不是感知层给的，而是情绪层根据 `blame` 事件算出来的**——这正好接上你要的"情绪有延续性"。

### 3.4 感知层的其他补强

| 项 | 改法 |
|---|---|
短消息走规则 | `text.length <= 2` 且无图 → 跳过感知，省一次调用 |
感知失败降级 | 用"上一轮情绪 + 规则读"兜底，并记一笔失败 |
certainty 校准 | 用"感知结果 vs 实际回复是否被用户继续"做离线校准（后期） |
emoji 利用 | 文本里的 emoji（😭😡🥲）作为情绪线索，不只靠图 |

## 四、查漏补缺（这次梳理新发现的）

| # | 缺口 | 影响 | 处理 |
|---|---|---|---|
1 | **感知层事件抽取缺失** | 情绪层没有输入 | 并入任务 2 |
2 | **场景事项没有 appraisal** | 情绪层无法"评价" | 并入任务 1 |
3 | **没有"她的一天"连续性** | 每天重复（咖啡/多肉） | 场景 v2 的 events 表 |
4 | **主动消息没有 chat 门槛** | 上班时间也发 | 场景 v2 输出 chat |
5 | **mood 是单一数字** | 无法表达"最近一直不对" | 情绪层 mood 层 |
6 | **冲突检测靠中文正则** | 容易误判 | 改用 place 枚举 |
7 | **感知失败无监控** | 15.5% 静默失败 | 加日志与周报 |
8 | **没有回复质量指标** | 改了不知道好坏 | 影子 + 三个指标（见第六节） |

## 五、可行性验证

### 5.1 依赖关系（有没有循环）

```
场景层 ──seeds/appraisal──→ 情绪层 ──tone/bias──→ 生成层
   ↑                                              │
   └──────── moodWeight（选场景加权）──────────────┘
```

有一条反馈环（情绪影响选场景），但**单向更新、每轮只算一次**，不会震荡。

### 5.2 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
prompt 变长，token 成本上升 | 每轮 +15% 左右 | 只把 seeds[0] 和 tone 一行放进 prompt |
场景/情绪参数难调 | 反复返工 | 全部走配置文件，不改代码 |
感知改字段影响旧代码 | 生成错乱 | `tone` 与 `emotion` 并存一版，灰度后删旧字段 |
情绪自激 | 她越聊越气 | 情绪只由事件改，不由生成结果改 |
模型不稳定（JSON 坏） | 感知失败 | 已有兜底，补"继承上一轮" |

### 5.3 每一步怎么验证

| 任务 | 验证方式 | 通过标准 |
|---|---|---|
场景 v2 | 时间旅行单测 + 覆盖率模拟 | 覆盖率 ≥ 90%，无空 seeds |
感知补强 | 用 246 条历史文本离线跑一遍 | 事件抽取准确率抽检 20 条 ≥ 80% |
情绪层 | 24 小时仿真 + 单测 | 曲线不失控，一天"生气"占比 5-10% |
裁决 v2 | 离线回放（已有脚本） | act 分布熵上升，连续 deflect = 0 |
集成 | 影子日志 1 天 | 抽 20 条，话与情绪对得上 ≥ 80% |

### 5.4 成本估算

```
每条消息：感知 1 次 + 生成 1 次（现在）
改造后：感知 1 次 + 生成 1 次（不变），场景/情绪是本地计算，零成本
仅在"情绪事件"发生时多一次数据库写入
```

**结论：不增加模型调用次数，只增加 prompt 里 2-3 行。**

## 七、建议顺序（修订版）

```
第 1 步  场景 v2（1.5 天）            ← 产出 appraisal + seeds
第 2 步  感知补强（0.5 天）            ← 产出 tone + event
第 3 步  情绪层（1.5 天）              ← 消费前两步
第 4 步  裁决 v2（0.5 天）
第 5 步  影子 + 灰度（1 天 + 观察）
```

**为什么感知补强插在中间**：它只改一个函数，但情绪层要靠它拿事件；不先做，情绪层只能靠猜。

---

## 八、一句话总结

```
感知层现在给的是"这句话什么味"，不是"她什么心情"。
情绪要独立成层，靠事件驱动；场景层负责产出事件。
顺序：场景 → 感知补强 → 情绪 → 裁决。
```
