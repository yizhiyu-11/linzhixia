## 二、由此推出的一天（上班族、独居）

| 时段 | 在做什么 | 手机可用度 | 适合聊天吗 |
|---|---|---|---|
00:18-07:10 | 睡（6.85h） | 无 | 不 |
07:10-07:40 | 起床、洗漱 | 低 | 勉强（刚醒，话短） |
07:40-08:10 | 早饭/出门 | 中 | 可以（碎聊） |
08:10-08:55 | 通勤 | **高**（地铁刷手机） | **很适合** |
09:00-12:00 | 上班 | 低 | 不适合（回复慢、短） |
12:00-13:00 | 午饭+眯一会 | **高** | 适合 |
13:00-18:00 | 上班 | 低 | 不适合 |
18:00-18:45 | 通勤回家 | **高** | 适合 |
18:45-19:40 | 买菜/做饭（家务） | 中 | 可以（手上有事） |
19:40-21:30 | 吃饭+刷手机（休闲） | **很高** | **最适合** |
21:30-22:30 | 家务/洗澡 | 中 | 可以 |
22:30-00:18 | 自由时间、睡前刷手机 | **很高** | **最适合（情绪最松）** |

### 三个关键洞察

**① 她的"可聊时间"不是均匀的**

```
一天里真正"随时能回"的只有 4 段：通勤、午饭、晚饭后、睡前
合计约 3.5 小时，占一天的 15%
```

这解释了为什么"上班时间主动找她"会显得假——真人那个点在开会。

**② 互联网 5h37m 是碎片**

不是连续 5 小时，而是"看一眼、放下、再看"。
所以她的回复应该是**短、断续、可中断**，而不是长篇大论。

**③ 深夜是情绪窗口**

6.85 小时睡眠、0:18 入睡——说明很多人 23 点后还在刷手机，且那时最松。
主动消息放这个时段，回复率最高。

## 三、对场景层的设计含义

### 3.1 场景池按"时间带"组织，不按小时

现在 40 条场景按 24 小时散着放，密度不均。改成 **6 个时间带**，每带 8-14 条：

```
① 早间      07:00-09:00   起床 / 早饭 / 通勤
② 上午      09:00-12:00   上班（场景要少而稳）
③ 午间      12:00-13:30   午饭 / 午休
④ 下午      13:30-18:00   上班
⑤ 晚间      18:00-21:30   通勤 / 做饭 / 吃饭
⑥ 夜间      21:30-00:30   家务 / 洗澡 / 刷手机 / 睡前
```

每带配：

```json
{
  "band": "晚间",
  "hours": [18, 21.5],
  "chatAvailability": 0.7,
  "pace": "normal",
  "scenes": [ ... ]
}
```

### 3.2 每个场景带 1-3 件"事项"

事项的生命周期按类型定：

| 类型 | 例子 | 时长 | done 保留 |
|---|---|---|---|
做饭 | 锅里的水快开了 | 20-40 分钟 | 1 小时 |
通勤 | 还有三站 | 40 分钟 | 30 分钟 |
家务 | 衣服泡在盆里 | 2-3 小时（跨场景） | 2 小时 |
工作 | 一版等着发出去 | 整个上午 | 到下班 |
吃饭 | 面快吃完了 | 15 分钟 | 1 小时 |

**家政类事项允许跨场景**——这是"生活感"的关键：她换了个场景，衣服还在泡着。

### 3.3 主动消息只在 `chatAvailability ≥ 0.5` 的时段发

```
09:00-12:00  0.2   几乎不发（在上班）
13:30-18:00  0.2   几乎不发
08:10-08:55  0.8   可以发（通勤）
12:00-13:00  0.8   可以发
19:40-21:30  0.9   最适合
22:30-00:18  0.9   最适合
```

这比现在"9 点到 23 点随便发"真实得多。

### 3.4 周末单独一套

```
起晚 1-2 小时（10 点后）
白天：社交 / 逛街 / 运动（购物 15min、运动 35min 的平均值在周末集中）
晚上：宅、追剧、点外卖
```

周末场景池单列，约 20-25 条。

## 四、B 方案的落地形态

### 4.1 新增数据文件

```
personas/life/day.json        工作日时间带 + 场景池
personas/life/weekend.json    周末时间带 + 场景池
```

放 `personas/` 下，是因为**不同角色可以有不同作息**（林知夏上班，未来角色可能是自由职业）。

### 4.2 scene.mjs 改动

```
getScene():
  1. 判定今天星期几 + 当前时间带
  2. 从该带场景池里选（避开最近 4 个）
  3. 生成 items（1-3 件，带 phase 与时长）
  4. 计算 seeds（done > doing > pending）
  5. 返回 { location, doing, items, done, seeds, pace, chat }

刷新：
  · 事项 done 时 60% 概率换场景
  · 最短 25 分钟、最长 90 分钟
```

### 4.3 与现有代码的兼容

```
pending 字段由 items 派生（旧 UI / proactive 不用改）
state 里旧 JSON 缺 items 时，用 doing 兜底
```

1 | 她的作息按哪种人 | 上班族 / 自由职业 / 学生 | **上班族**（和大多数人同步，聊天时段自然） |
