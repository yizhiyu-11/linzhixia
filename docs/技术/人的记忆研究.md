# 人的记忆是怎么工作的 · 对照我们的设计

> 先弄清人类记忆的事实，再回答"按相关性召回 + 三条规则"这套设计行不行。

---

## 一、结构：不是一个仓库，是几个

### 1.1 三级模型（Atkinson-Shiffrin）

```
感觉记忆    <1 秒，容量大，不加工就没了
短时记忆    15-30 秒，容量 7±2
长时记忆    近乎无限，靠复述进入
```

### 1.2 工作记忆（Baddeley）

不是"短时仓库"，而是一组**带处理能力的暂存区**（语音环路、视空间画板、中央执行）。
容量更小：**4±1 个组块**。

**对我们的含义**：她一次能"拿着"的事就 3-4 件。我们设计召回 3 条，正好在工作记忆容量内；把 10 条消息全塞进 prompt，其实超出了人类一次能同时顾及的量。

### 1.3 情节 vs 语义（Tulving, 1972）

```
语义记忆   事实，脱离情境   "猫是哺乳动物""他叫陈子鹏"
情节记忆   带时间地点和感受 "上周三他在地铁上说腿疼，语气不太好"
```

**对我们的含义**：我们的 `facts` 是语义记忆，`messages` 是原始流水——**缺了情节记忆这一层**（带情境的事件）。

## 二、编码：怎么记进去的，决定能记多久

### 2.1 加工深度（Craik & Lockhart）

```
浅加工（字形、读音）→ 记不住
深加工（意义、和自己有关）→ 记得牢
```

**含义**：抽事实时如果只抓关键词（"腿疼"），不抓意义（"他膝盖有旧伤，下雨就疼"），记不久也用不上。

### 2.2 情绪唤醒增强记忆（杏仁核）

高唤醒事件（生气、害怕、特别开心）会被优先巩固。杏仁核通过多条通路调节海马的可塑性。

**含义**：我们设计里"情绪显著度"加权是对的，但**权重应该在编码时按当时的唤醒度打**，不是检索时估。

### 2.3 编码特异性（Tulving & Thomson）

> 提取的效果，取决于提取时的线索和编码时的情境有多匹配。

同一件事，在"当时的气味、地方、心情"下更容易想起来。

**含义**：只按文字相似度召回是不够的。**话题 + 当时的情绪 + 当时的场景**都该是线索。

一条经验：

```
他说"腿疼"时她正在地铁里、他心情不好
下次再提腿，如果也在通勤、也心情差 → 更容易想起来
```

## 三、巩固与再巩固

### 3.1 睡眠巩固

慢波睡眠期间，海马会把当天的记忆"重放"给皮层，转成长期存储。

**含义**：日摘要应该放在**夜里**做（现在 summarize 是定时的，可以对齐到睡前），而不是白天随时切。

### 3.2 再巩固（reconsolidation）

记忆被提取后会短暂变得不稳定，**重新存回去时可能被修改**——这是记忆会被"改写"的机制。

**含义（两面）**：

```
风险：她可能"记错"，而且越提越偏
机会：他纠正她之后，记忆可以被真的改对
```

设计上应该：**每次被纠正就覆盖旧记忆**（我们现在的 facts 是覆盖式，这点是对的）。

## 四、提取：不是搜索，是重建

### 4.1 线索依赖提取

遗忘经常不是"丢了"，是**没有合适的线索**（cue-dependent forgetting）。

### 4.2 重构（Bartlett）

记忆不是录像回放，是**用图式重建**——每次回忆都会掺进当下的理解。

### 4.3 模糊痕迹理论（fuzzy-trace）

人同时存两套痕迹：

```
逐字痕迹（verbatim）  很快丢失
要点痕迹（gist）      保留很久
```

正常人几天后记得"他说腿疼"，不记得原话是"膝盖有点酸"。

**含义（很重要）**：

```
我们存 7 天原文 + 日摘要 —— 方向对，但摘要应该是"要点 + 实体"，不是聊天记录改写
她说话时不该复述原话，该说要点
```

### 4.4 元记忆（metamemory）

人知道自己"记不清"。舌尖现象、知道感（feeling of knowing）都是元记忆。

**含义**：她应该有"我记不太清了"这种表达，比硬编一个细节好得多。硬编才是露馅的地方。

---

## 五、遗忘：不是单纯衰减

### 5.1 两条机制

```
衰减   随时间变淡（Ebbinghaus 曲线）
干扰   相似记忆互相压制：前摄干扰（旧的干扰新的）、倒摄干扰（新的干扰旧的）
```

**含义**：如果我们把"他今天吃了面""他昨天吃了面""他前天吃了面"都存着，它们会互相干扰，反而谁都记不清。**相似事件应该合并成一条**（"最近老吃面"）。

### 5.2 怀旧偏置（reminiscence bump）

人对**初恋、第一次**这类早期重要事件记得格外清楚。

**含义**：关系早期的记忆（第一次聊天、第一次吵架）应该永久保留并加权——这是"我们的故事"的锚点。

## 六、逐条对照我们的设计

| 人类记忆的事实 | 我们的设计 | 判定 |
|---|---|---|
工作记忆 4±1 组块 | 最近 10 条 + 召回 3 条 | ⚠ 召回 3 条合适，10 条偏多 |
情节记忆独立于语义 | 只有 facts + 原始消息 | ❌ 缺情节层 |
记要点不记原话 | 存原文 7 天 + 摘要 | ⚠ 摘要需改成"要点+实体" |
提取靠线索（情境匹配） | 只按关键词/话题 | ❌ 缺情绪、场景线索 |
相似记忆互相干扰 | 没有合并去重 | ❌ 缺 |
情绪增强记忆 | 有情绪显著度加权 | ✅ 对，但要在编码时打 |
睡眠巩固 | 日摘要定时跑 | ⚠ 应对齐夜间 |
再巩固（越提越偏） | facts 覆盖式 | ✅ 对 |
元记忆（知道自己记不清） | 没有 | ❌ 缺，容易硬编 |
怀旧偏置（早期事件重） | 没有 | ⚠ 可选，建议加 |

**结论：设计方向成立，但有 5 处要改。**

## 七、修订后的设计

### 7.1 记忆分三层（补上情节层）

```js
// 语义：稳定事实
{ kind: 'fact', key: '膝盖', value: '下雨会疼', confidence: 0.9, since: 10 天前 }

// 情节：带情境的事件
{ kind: 'episode', text: '地铁上说腿疼，那天她也在通勤，他心情不好',
  at: 时间, place: 'commute', mood: -0.4, importance: 4 }

// 关系：锚点
{ kind: 'anchor', text: '第一次聊天是 10 月 22 日晚上', importance: 5 }
```

### 7.2 编码时就打三个标签

```
importance  1-5（由事件影响 + 情绪唤醒度决定）
affectTag   -1..1（当时他/她的情绪）
context     地点 + 时段（供编码特异性匹配）
```

### 7.3 检索用三路线索

```
score = 0.35 文本/话题相关
      + 0.20 情境匹配（同地点/同时段/同情绪）
      + 0.25 重要性
      + 0.20 新鲜度（半衰期 7 天，锚点不衰减）
```

### 7.4 加"干扰控制"

```
同 key 的相似事件，7 天内合并成一条（"最近老吃面"×3）
合并时保留最强的情绪标记
```

### 7.5 加"元记忆"表达

```
confidence < 0.5 → 允许她说"我记不太清了，是不是…"
confidence < 0.3 → 不说细节，只接情绪
```

**这一条比多存 100 条记忆更能提升真实感。**

### 7.6 巩固放夜里

```
23:30-00:30  生成日摘要（要点 + 实体）
每周日      合并成周摘要
```

## 八、这套设计能不能落地的判断

| 维度 | 判断 |
|---|---|
技术可行性 | ✅ 全是本地计算 + 已有表结构，改动集中在 memory.mjs 和新增 retrieve.mjs |
成本 | ✅ 不增加模型调用（编码时的一次摘要已有；检索本地算） |
风险 | ⚠ 召回不准会串味 → 用 confidence 门槛 + 抽检 |
风险 | ⚠ 记错被用户发现 → 元记忆表达兜底 |
与情绪层的配合 | ✅ 情绪标记的事件能被重新点燃，互相增强 |

**结论：可行，但顺序要调整——先把"存对"（gist + 三标签）做好，再谈"召回"。**

## 九、修正后的任务顺序

```
1  场景层 v2                    1.5 天
2  感知补强                      0.5 天
3  记忆补强：
   3.1 事实抽取修好（facts 只有 1 条）
   3.2 摘要改成要点+实体，接入 prompt
   3.3 情节层（episodes 表 + 三标签）
   3.4 检索（三路线索 + 干扰合并 + confidence 门槛）
   3.5 元记忆表达                       合计 1.5 天
4  情绪层                        2 天
5  裁决层 v2                     0.5 天
```
