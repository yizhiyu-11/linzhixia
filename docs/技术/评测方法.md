# 怎么测：语料跑批与判定

> 目的：让改动**有数据支撑**，而不是"感觉变好了"。

---

## 一、三层测试

| 层 | 跑什么 | 花不花钱 | 什么时候跑 |
|---|---|---|---|
单元测试 | `scripts/test-*.mjs` | 免费 | 每次改代码 |
语料跑批 | `scripts/run-corpus.mjs` | 每轮约 ¥0.005 | 改 prompt / 感知 / 裁决 |
人工抽检 | 看跑批结果 | 免费 | 每批抽 20 条 |

CI 里只跑第一层（不需要 Key）。

---

## 二、单元测试

```bash
node scripts/smoke.mjs          # 冒烟：人设拼装、SQLite、安全分类、熔断、分条
node scripts/test-scene-v2.mjs  # 场景层：时间带、事项生命周期、seeds 兜底
node scripts/test-uaffect.mjs   # 用户情绪模型：38 项断言
node scripts/test-proactive-check.mjs  # 主动消息：指向性、去重、长度
```

**注意**：涉及时间的断言要显式传 `hour`，否则不同时区的机器结果不同（CI 用 UTC，本地用东八区，曾因此挂过）。

---

## 三、语料跑批

仓库只带 `test/corpus/sample-100.jsonl`（100 条样例，25 个分类各 4 条）。
完整评测集（5000 条）不公开，避免评测集被"背答案"。

```bash
# 用样例跑一轮（不连 QQ，假 OneBot）
node --env-file=.env scripts/run-corpus.mjs test/corpus/sample-100.jsonl \
  --out test/runs/run-sample.jsonl

# 规则判定（免费）
node scripts/judge-run.mjs test/runs/run-sample.jsonl
```

输出：`run-sample.report.json` + `.REPORT.md`。

### 看三个数

```
硬失败率      空回复 / 只有标点 / 说了"我重复了"这类
首响延迟      p50 / p90
act 分布      全落在 answer 说明裁决层没起作用
```

### 硬失败的定义（judge-run.mjs）

```
H1  点评对方说话方式（"你又重复了"）
H2-H4 场景矛盾（说在家却在公司）
H5  空回复 / 只有标点
```

## 四、人工抽检

跑完批，从 `run-*.jsonl` 里随机抽 20 条，逐条看：

```
① 回得对不对（有没有答非所问）
② 像不像这个人（语气、长度、口癖）
③ 有没有出戏（提到 AI、自称鲸鱼、长篇大论）
```

只看三件事，不用给分。

---

## 五、改动前后对比

```bash
# 改之前
node --env-file=.env scripts/run-corpus.mjs test/corpus/sample-100.jsonl --out test/runs/before.jsonl

# 改之后
node --env-file=.env scripts/run-corpus.mjs test/corpus/sample-100.jsonl --out test/runs/after.jsonl

# 对比（脚本在 scripts/compare-metrics.mjs，需要自己接参数）
```

对比时只看四项：硬失败率、平均长度、空回复数、act 分布。

---

## 六、别做的事

```
✗ 只跑一条就觉得改好了
✗ 用"我觉得更像了"当结论
✗ 用完整 5000 条评测集来回调参（会过拟合）
```

一次只改一处，跑一遍，看四个数，再决定下一步。
