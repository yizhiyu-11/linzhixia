# 场景层：输出契约 + 通用模板方案

> 先回答"场景层要给什么结果"，再谈怎么给。
> 目标：一套**与角色无关**的模板，换人设只换参数，不用重写代码。

---

## 一、先说需求：谁在等场景层的输出

| 消费方 | 它需要知道什么 | 用来做什么 |
|---|---|---|
裁决层 | 她**有没有话可说**、**方不方便聊** | 决定 advance 允不允许、要不要短 |
生成层 | 她**此刻在干嘛**、手头**哪件事** | 写进 prompt，让话有具体指涉 |
主动消息 | **说什么**、**该不该现在说** | 选 seeds[0]、按 chat 概率 |
冲突检测 | 她**在哪个语义地点** | 判断回复有没有说错地方 |
后台 UI | 人话版本的"她在哪、在干嘛" | 展示 |
记忆/事件 | 她今天**做过什么** | 长期引用（第二阶段） |

**结论：场景层要输出 4 类东西——位置、事项、可聊能力、可讲素材。**

## 二、输出契约（`getScene()` 的返回值）

### 2.1 字段定义

```js
{
  // ── 位置 ──
  location: '家',            // 展示用中文，进 prompt
  place: 'home',             // 枚举：home|commute|work|outside|bed|shop
  band: 'evening',           // 时间带：morning|forenoon|noon|afternoon|evening|night
  weekday: 3,                // 0-6，0=周日

  // ── 状态 ──
  doing: '在厨房煮面',        // 一句话，进 prompt + UI
  since: 1793...,            // 本场景开始时间
  minutes: 12,               // 已持续分钟

  // ── 事项（核心） ──
  items: [
    {
      id: 'i1',
      text: '锅里的水快开了',
      kind: 'meal',          // chore|work|meal|commute|leisure
      phase: 'doing',        // pending|doing|done
      at: 1793...,           // 开始时间
      expectMin: 25,         // 预计持续
      doneAt: null
    }
  ],

  // ── 可讲素材（已排序，最多 3 条） ──
  seeds: [
    { text: '衣服晾完了', source: 'done', kind: 'chore', weight: 0.9 },
    { text: '锅里的水快开了', source: 'doing', kind: 'meal', weight: 0.7 }
  ],

  // ── 可聊能力 ──
  pace: 'normal',            // busy|normal|quiet，影响回复长度
  chat: 0.7,                 // 0-1，可聊度，主动消息按它打折
  interruptible: true,       // 能不能被打断（开会=false）

  // ── 兼容旧字段 ──
  pending: [{ text, at }]    // 由 items 中 phase≠done 派生
}
```

### 2.2 不变式（必须始终成立）

```
① seeds 至少 1 条（否则场景层失职）
② location 必须在语义表里（否则冲突检测会瞎）
③ done 的事项 doneAt ≤ now，且保留不超过 2 小时
④ chat 与 pace 一致：busy → chat ≤ 0.3；quiet → chat ≥ 0.6
⑤ items 数量 1~3，phase 分布合理（不能 3 件都是 done）
```

### 2.3 失败兜底

```
模板缺失 / JSON 坏 / 时间段没覆盖 → 退回现有 40 条场景池
（保证不会因为模板问题让机器人不说话）
```

## 三、通用模板怎么分层

三层，换角色只改最上层：

```
① template   结构：时间带划分、字段规则、事项类型
② preset     作息：上班族 / 自由职业 / 学生 / 夜班（起床、通勤、上班、睡觉）
③ persona    这个角色的个性化：作息微调、专属场景、口头禅
```

### 3.1 目录

```
personas/life/
  template.json          结构定义（不含具体场景）
  scenes/
    common.json          通用场景（约 60 条，所有人共享）
    office.json          上班族专属（约 30 条）
    freelance.json       自由职业（约 25 条）
    student.json         学生（约 25 条）
  presets/
    office.json          作息参数
    freelance.json
    student.json
  personas/
    lzx.json             林知夏的覆盖项（可选）
```

### 3.2 preset 长什么样

```json
{
  "id": "office",
  "name": "上班族",
  "wake": 7.2,
  "leave": 8.2,
  "workStart": 9,
  "lunch": [12, 13],
  "workEnd": 18,
  "home": 18.8,
  "sleep": 0.3,
  "commuteMin": 45,
  "chatCurve": {
    "morning": 0.5,
    "forenoon": 0.2,
    "noon": 0.8,
    "afternoon": 0.2,
    "evening": 0.7,
    "night": 0.9
  }
}
```

**时间带不是写死的**，由 preset 的 `wake/leave/workStart/lunch/workEnd/home/sleep` 算出来。
所以自由职业（无通勤、起床晚）不用改代码，只换参数。

### 3.3 场景条目长什么样

```json
{
  "id": "office_evening_cook",
  "band": "evening",
  "place": "home",
  "location": "家",
  "doing": "在厨房煮面",
  "pace": "normal",
  "chat": 0.7,
  "items": [
    { "text": "锅里的水快开了", "kind": "meal", "expectMin": 20 },
    { "text": "碗还没洗", "kind": "chore", "expectMin": 120, "carry": true }
  ]
}
```

`carry: true` = 允许跨场景延续（家务类）。

### 3.4 模板只定义规则，不定义内容

`template.json` 里写的是：

```json
{
  "bands": ["morning", "forenoon", "noon", "afternoon", "evening", "night"],
  "itemRules": {
    "chore":  { "expectMin": [30, 180], "carry": true,  "doneKeepMin": 120 },
    "work":   { "expectMin": [60, 240], "carry": false, "doneKeepMin": 60 },
    "meal":   { "expectMin": [15, 40],  "carry": false, "doneKeepMin": 60 },
    "commute":{ "expectMin": [20, 60],  "carry": false, "doneKeepMin": 30 },
    "leisure":{ "expectMin": [30, 90],  "carry": false, "doneKeepMin": 60 }
  },
  "seedsRule": { "max": 3, "order": ["done", "doing", "pending"] },
  "refresh": { "minMin": 25, "maxMin": 90, "doneSwapChance": 0.6 }
}
```

换角色只换 `presets/*.json` + `scenes/*.json`，`template.json` 不动。

## 四、判断与分析：这样设计够不够用

### 4.1 裁决层够不够

裁决要三个判断，契约里都有：

```
有没有话可说     seeds.length > 0
方不方便长聊     pace !== 'busy'
能不能现在主动   chat >= 0.5 && interruptible
```

**够用。**

### 4.2 生成层够不够

生成需要"具体指涉"，契约给了 `seeds[0].text`。

但有个细节要注意：**seeds 是"可讲"，不是"必须讲"**。所以 prompt 要写成：

```
【手头的事】${seeds[0].text}（可以提，也可以不提，别提第 2 次）
```

否则会变成每轮报备。

### 4.3 主动消息够不够

```
说什么       seeds[0]
该不该发     chat（作为概率乘数）
语气         pace
```

**够用。** 但 chat 只能做"概率打折"，不能做"绝对禁止"——否则深夜 0.9 也只能一天 3 条。

### 4.4 冲突检测够不够

现在 `findConflict` 只看 location 字符串匹配。新契约提供 `place` 枚举，可以做得更准：

```
她 place=work，回复里出现"我在家躺着" → 冲突
她 place=commute，回复里出现"我在厨房" → 冲突
```

**建议把冲突检测也改成基于 place，而不是中文正则。** 这是顺带的收益。

### 4.5 UI 够不够

`location + doing + items` 已经够展示。`items` 能让后台看到"她手头还有什么没做"，比现在丰富。

## 五、落地计划（三步）

### 第一步：契约 + 数据 + 场景核心（1 天）

```
□ template.json（规则）
□ presets/office.json（先只做上班族）
□ scenes/common.json + scenes/office.json（约 90 条）
□ scene.mjs 重写：
    读 preset → 算时间带 → 选场景 → 生成 items → 生命周期 → 算 seeds
    保留 pending 字段，旧调用方不用改
□ scripts/test-scene.mjs：时间旅行单测（0/20/40/70 分钟、工作日/周末）
□ scripts/scene-coverage-sim.mjs 回归：覆盖率应 ≥ 90%
```

### 第二步：消费方接入（0.5 天）

```
□ brain.mjs：sceneBlock 用 seeds[0]，加 pace 控制长短
□ proactive.mjs：用 chat 做概率乘数，用 seeds[0] 做理由素材
□ index.mjs：findConflict 改用 place
```

### 第三步：验证（观察期）

```
□ 影子日志：记录每轮 seeds 来源（done/doing/pending）
□ 线上 1 天：看主动消息里"具体事件"占比
□ 指标：seeds 覆盖率 > 90%、advance 触发率 ~40%、空消息（<8 字）< 5%
```

## 六、风险

| 风险 | 应对 |
|---|---|
场景写太多，维护不动 | 先把 common 控制在 60 条，够用再加 |
模板太抽象，写起来绕 | template 只写规则，内容全在 scenes，写的人不用懂代码 |
换角色要改代码 | preset 参数化，时间带由参数算，不写死 |
旧数据不兼容 | 缺字段一律 `?? []` 兜底，并保留 pending |

---

## 七、需要你确认的三点

| # | 问题 | 我的建议 |
|---|---|---|
1 | 事项数量 1~3 件是否合适 | **合适**，多了像待办清单 |
2 | seeds 最多 3 条够不够 | **够**，裁决只用第 1 条 |
3 | 冲突检测要不要顺手改成 place 枚举 | **要**，比中文正则准，改动小 |

确认后我按第一步开始写数据文件和 `scene.mjs`。
