# 模型接入与成本

> 只调两次模型，一轮约 ¥0.007-0.01。本文说明怎么接、为什么这么便宜、以及哪些省钱方案试过但放弃了。

---

## 一、接模型

只要 OpenAI 兼容接口，改三个环境变量：

```bash
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_MODEL=deepseek-chat
```

代码里所有调用都走 `src/brain.mjs` 的 `chat()`，没有第二处。

---

## 二、为什么一轮只要两次调用

| 层 | 是否调模型 | 理由 |
|---|---|---|
感知 | ✅ 是 | 要读懂语气、意图、谁对谁做了什么 |
场景 | ❌ 否 | 按作息和场景池用规则抽 |
情绪 | ❌ 否 | 事件注入 + 半衰期衰减，用规则算 |
记忆 | ❌ 否 | 关键词 + 时间衰减检索 |
裁决 | ❌ 否 | 规则 + 阈值 |
生成 | ✅ 是 | 说人话必须靠模型 |

**合成一次调用可以省 30%，但输出 JSON 和输出人话是两种模式，放一起会互相污染。**
这是刻意保留的成本。

## 三、成本表

官方价（元 / 百万 token，[来源](https://api-docs.deepseek.com/quick_start/pricing)）：

| | 谷时 | 高峰（×2） |
|---|---|---|
输入（缓存未命中） | 1.07 | 2.14 |
输入（缓存命中） | 0.021 | 0.042 |
输出 | 4.26 | 8.52 |

高峰：**周一至周五北京时间 09:00-12:00、14:00-18:00**；其余时间（含周末）谷时。

实测（最近 7 天，574 次调用，227 轮）：

```
每轮 ¥0.0070（按真实时段）
每轮 ¥0.0101（全按高峰，一般情况估算）
缓存命中率 67%（输入 token 口径）
```

按任务拆：

```
生成回复 59%　感知 23%　主动消息 7%　看图 7%　其余 4%
```

## 四、省钱的三个办法（按有效程度）

### 1. 前缀缓存（已做，效果最大）

DeepSeek 按**前缀完全匹配**缓存，命中价是未命中的 1/50。

做法：把每轮不变的内容放前面，变的内容放最后。

```
【名字/背景/性格/说话方式】   ← 静态
【必须遵守】【打字习惯】      ← 静态
【参考语气】fewShots          ← 静态（占比最大）
─────────── 以上可缓存 ───────────
【关系】【事实】【摘要】【时间】【场景】【情绪】【记忆】
```

**反面教材**：把 `【时间】` 放在事实之前，缓存从第 600 token 就断了，后面 1700 token 全按全价收费。

实测：重排之后，同一句连发三次的命中率 88%；线上多用户交替时约 67%。

### 2. 谷时优先（已做，只影响统计）

晚上和周末是半价。聊天本来就集中在晚上，所以**实际账单比"全高峰"估算低约 30%**。

非实时任务（事实抽取、摘要）如果挪到谷时，还能再省一点——但这些只占 4%，收益很小。

### 3. 降级链（未做，规划中）

```
本地模型（隧道） → 云端 API → 备用 API
```

判定：调用超时 2.5 秒 / 连接错误 / 5xx → 立刻切下一个；连续成功 2 次切回。

**注意**：只让感知走本地，生成永远走云端——生成模型一换，语气就变了，用户会立刻察觉。

## 五、试过但放弃的方案

### 本地小模型做感知（2026-11-01 实测）

```
环境：RTX 4060 Laptop 8GB + Ollama 0.40 + Qwen3-1.7B
配置：think=false，format=json，走 /api/chat
```

链路是通的，质量不够：

| 指标 | 结果 |
|---|---|
JSON 成功率 | 6/6 |
平均耗时 | 836ms |
**情绪+意图与云端一致** | **1/6** |
事件判断（谁对谁做了什么） | 几乎全是 ignore |

原因：1.7B 能识别"情绪大概对"，但**意图和事件判断基本没学会**。而事件判断是情绪层和裁决层的输入，错了后面全歪。

结论：**除非换 8B（2-3 秒延迟），否则本地感知会让她"读不懂话"**，得不偿失。

坑：Qwen3 默认开思考模式，`max_tokens` 全烧在推理上，`content` 返回空字符串；必须 `think: false`，且 Ollama 的 OpenAI 兼容端点（`/v1`）不认这个参数，得走原生 `/api/chat`。

### fewShots 瘦身（未做）

55 条 → 30 条能省 19% 输入，但语气会变淡。**风格比省几毛钱重要**，暂不采纳。

### 多模型投票 / 融合（不做）

成本翻倍、延迟翻倍，陪伴场景要的是快和像人，不是答得最准。

## 七、如果要换供应商

只要满足两点：

```
1. OpenAI 兼容（/v1/chat/completions）
2. 返回 usage.prompt_tokens / completion_tokens
```

改 `.env` 里的 `DEEPSEEK_*` 即可，代码不用动。

缓存字段是可选的：返回 `prompt_cache_hit_tokens` 就按命中价算，不返回就按全价算。
