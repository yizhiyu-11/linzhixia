# 架构说明

> 一次 QQ 消息进来，到她回出去，中间发生了什么。
> 本文只描述**代码里真实存在的东西**，不写设想。

---

## 一、为什么不是"把 prompt 丢给模型"

单纯把聊天记录塞进 prompt，能得到"能回话"，但得不到"像人"：

| 问题 | 表现 |
|---|---|
不知道现在几点 | 凌晨说"该吃午饭了" |
没有自己的生活 | 每句都在等你说话，从不说自己在干嘛 |
情绪是平的 | 被骂了还是同一个语气 |
记不住 | 第三天问"我膝盖还疼吗"，她说"哪次" |
每次都说差不多的话 | 不管你说什么，都先接一句再反问一句 |

所以拆成六层，每层只管一件事。

## 二、六层

```
QQ / OneBot
   │
   ▼
┌─────────────────────────────────────────────┐
│ 感知 perceive   这一次他说了什么、什么语气、冲谁   │  ← 模型调用 1
├─────────────────────────────────────────────┤
│ 场景 scene      她这会儿在哪、在干嘛、手头什么事   │  ← 本地规则
├─────────────────────────────────────────────┤
│ 情绪 affect     她的三轴状态（效价/唤醒/精力）     │  ← 本地规则
│      uaffect   他对她的影响（独立建模）           │
├─────────────────────────────────────────────┤
│ 记忆 recall     事实 / 情节 / 摘要，挑相关的       │  ← 本地规则
├─────────────────────────────────────────────┤
│ 裁决 act        这一轮接住、先接情绪、还是说自己的   │  ← 本地规则
├─────────────────────────────────────────────┤
│ 生成 brain      拼 prompt，说人话                │  ← 模型调用 2
├─────────────────────────────────────────────┤
│ 投递 deliver    分条、打字节奏、配表情包、发语音     │  ← 本地规则
└─────────────────────────────────────────────┘
```

**一轮只调两次模型**（感知 + 生成），其余全是本地计算。
这是成本与延迟的底线，也是与"每轮都过一遍 agent"的框架最大的不同。

## 三、一次对话的完整时序

以 `src/index.mjs` 的 `handleMessage` 为准（行号会漂，看函数名）：

```
1  消息进来
   ├─ 白名单校验
   ├─ 表情包 / 图片 / 语音识别（可选）
   └─ 短消息走快路径（"嗯""哦"不调感知）

2  scene = getScene(memory, qq, persona)
   按 persona.life 的作息算时间带 → 抽一个场景
   场景里带 items（她手头的事），有生命周期：待办 → 进行中 → 完成

3  perce = await perceive(...)              ← 模型调用 1
   输出：情绪标签+强度、意图、话题、连续性、他对她做了什么
   失败 → 退回规则判断（read.mjs），不影响主流程

4  act = decideAct({...})
   输入：感知结果 + 她的情绪 + 场景 + 最近几轮的姿态
   输出：engage / advance / answer / deflect / ignore + strength

5  记忆召回
   ├─ facts     事实表（长期）
   ├─ episodes  情节（带时间地点）
   └─ summaries 摘要（滚动压缩）
   拼成 recallHint

6  generateReply(...)                       ← 模型调用 2
   prompt 顺序：静态人设 → 规则 → fewShots → 动态（事实/场景/情绪/记忆）
   静态在前是为了命中 DeepSeek 的前缀缓存

7  护栏与重试
   ├─ 空回复 / 只有标点 → 重生成
   ├─ 太像"点评对方说话" → 重生成
   └─ 情绪不匹配 → 重生成（有上限）

8  splitIntoBursts + deliver
   按 ||| 分条，按字数算打字节奏，可选配表情包 / 语音

9  落库
   ├─ messages    原始往来
   ├─ turns       这一轮的完整快照（感知/裁决/场景/耗时/花费）
   ├─ usage       每次模型调用的 token 与费用
   └─ episodes    值得记住的事（带时间、地点、情绪）
```

## 四、关键设计取舍

### 1. 感知与生成分开

```
合成一次调用省 30% 成本，但生成会被"分析任务"的格式要求带偏
（输出 JSON 和输出人话是两种模式，放一起会互相污染）
```

### 2. 情绪用规则算，不用模型判断

```
模型判断"她现在多生气"不稳定、不可复现、还贵
改成：感知给出事件（被骂 -0.7），情绪层用半衰期衰减算状态
好处：可解释、可回放、可调参
```

### 3. 记忆分三种，各有各的检索方式

| 类型 | 存什么 | 检索 |
|---|---|---|
facts | 稳定事实（不吃香菜、膝盖疼） | 全量注入（40 条上限） |
episodes | 发生过什么（带时间地点） | 关键词 + 时间衰减 |
summaries | 滚动摘要 | 每 N 轮压缩，直接注入 |

### 4. 场景用数据驱动，不写死在代码里

```
personas/life/presets/*.json   作息（几点起、几点上班）
personas/life/scenes/*.json    场景池（地点、在干嘛、手头的事）
```

人设可以自带生活：`persona.life` 里写 `preset` 和 `scenes`，就用自己的；
不写就退回 `office` + 通用场景池。

### 5. prompt 静态前置

```
【名字/背景/性格/说话方式】+【规则】+【fewShots】  ← 每轮完全一样
【时间】【事实】【摘要】【场景】【情绪】            ← 每轮都变
```

把变的部分放最后，前面 1700 tokens 就能命中 DeepSeek 的上下文缓存。
实测命中率约 67%（多用户交替时会掉，因为历史前缀不同）。

## 五、目录

```
src/
  index.mjs       主流程（唯一入口，串起所有层）
  perceive.mjs    感知：一句话 → 结构化判断
  scene.mjs       场景：时间带 + 场景池 + 事项生命周期
  affect.mjs      她的情绪：事件注入 + 半衰期 + 标签
  uaffect.mjs     他的情绪：从行为信号推断，带置信度
  recall.mjs      记忆检索：关键词、情节、摘要
  memory.mjs      SQLite 全部读写（13 张表）
  act.mjs         裁决：这一轮该怎么接
  brain.mjs       拼 prompt + 调模型 + 护栏重试
  persona.mjs     人设加载 + system prompt 组装
  delivery/reply  分条、打字节奏
  deliver.mjs     发出去（文本 / 表情包 / 语音 / 图片）
  proactive.mjs   主动消息
  life.mjs        作息与活动
server/           后台 HTTP 接口
web/              后台前端（React + Vite）
personas/         人设 + 生活配置
installer/        Windows 安装向导、自检、诊断、修复
scripts/          构建、测试、数据工具
```

## 六、数据表

| 表 | 装什么 |
|---|---|
`users` | 用户与昵称 |
`messages` | 原始往来（含日期，跨天会打时间前缀） |
`turns` | 每轮快照：感知、裁决、场景、耗时、花费 |
`usage` | 每次模型调用：token、缓存命中、费用 |
`facts` | 长期事实 |
`episodes` | 情节记忆（时间、地点、情绪） |
`summaries` | 滚动摘要 |
`relation` | 关系阶段与亲密度 |
`perceptions` | 感知原始输出（审计用） |
`media_seen` | 看过的图片 |
`sticker_stats` | 表情包效果（发了之后对方接不接） |
`scene_log` | 场景切换日志 |
`state` | 键值状态（情绪事件、主动消息计数等） |

## 七、成本与延迟

| 项 | 数值 |
|---|---|
每轮模型调用 | 2 次 |
每轮输入 | 约 3000-3400 tokens |
每轮输出 | 约 40-90 tokens |
每轮费用（高峰价） | 约 ¥0.010 |
每轮费用（谷时） | 约 ¥0.007 |
缓存命中 | 约 67% 输入 token |

价格按 [DeepSeek 官方](https://api-docs.deepseek.com/quick_start/pricing)：工作日 09-12、14-18（北京时间）为高峰，其余为谷时，谷时半价。

## 八、扩展点

| 想加什么 | 改哪里 |
|---|---|
新的人设 | `personas/*.json`（单文件，可自带生活） |
新的作息 / 场景 | `personas/life/` |
新的情绪事件类型 | `perceive.mjs` 的 `EVENT_KINDS` + `affect.mjs` 的映射 |
新的记忆类型 | `memory.mjs` 建表 + `recall.mjs` 加检索 |
换模型 | `.env` 里的 `DEEPSEEK_*`（OpenAI 兼容即可） |
关掉某一层 | `.env` 里的 `PERCEIVE` / `ACT_LAYER` / `UAFFECT` 等开关 |
